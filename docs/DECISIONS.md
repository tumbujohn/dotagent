# DECISIONS.md — Institutional Memory

## D1 — Engineering Constitution and mini-skills live inline in CLAUDE.md, not as separate skill files

**Context:** The repo has both a `skills/` folder (installable `.claude/skills/` packages) and a root `CLAUDE.md` (copied wholesale into project roots). The Engineering Constitution and four mini-skills (Goal-Driven Backcasting, Product Maturity Review, UIUX Design Mode, Documentation System) could have been extracted into `skills/engineering-constitution/SKILL.md` etc.

**Decision:** Keep them inline in `CLAUDE.md`.

**Alternatives considered:** Extract each into its own `skills/<name>/SKILL.md` and have `CLAUDE.md` reference them.

**Reasoning:** `CLAUDE.md` is meant to be portable as a single file copy-paste into a new project's root, active immediately with no separate install step. Requiring a target project to also copy multiple skill folders into `.claude/skills/` before the constitution/mini-skills work would break that single-file portability.

**Consequences:** `skills/engineering-constitution/SKILL.md` now carries the full constitution text under standard `SKILL.md` frontmatter (`name`/`description`), so it can be installed standalone into a project's `.claude/skills/` when only the constitution — not the rest of `CLAUDE.md` — is wanted. `CLAUDE.md`'s inline copy remains the source of truth for portability; the skill file is a duplicate for discoverability and standalone use, so a change to one must be mirrored in the other. See [TODO.md](TODO.md).

## D2 — `rules/` and `skills/` are kept as separate mechanisms

**Context:** Both folders hold reusable instruction text, but in different formats.

**Decision:** `skills/` follows the Claude Code `SKILL.md` package convention (frontmatter with `name`/`description`, invoked via `/skill-name`). `rules/` holds flatter, tool-agnostic snippets, including the Cursor/Windsurf `trigger: always_on` convention, meant to be pasted into whatever mechanism a given tool (Claude Code, Cursor, Windsurf, Gemini CLI) uses for always-on instructions.

**Reasoning:** Not every target project uses Claude Code specifically; `rules/` is the lowest-common-denominator format that works by copy-paste anywhere, while `skills/` is Claude-Code-specific and gets the richer package treatment.

**Consequences:** Contributors must pick the right folder for a new instruction based on what mechanism it targets, not just its content (see [DEVELOPMENT.md](DEVELOPMENT.md)).

## D3 — Known duplication between CLAUDE.md and rules/gemini-agent-rules on migration policy

**Context:** `CLAUDE.md` states "Never create a destructive migration only additive" under `## Database Operations`. `rules/gemini-agent-rules` independently states "Always ensure migrations are not destructive and only adds so as not to cause issues when updating a live system," plus related DB rules (SQLite→MySQL portability, using migration facilities over raw SQL).

**Decision (as of this review):** Leave both in place for now rather than merging, since `rules/gemini-agent-rules` carries additional PHP/DB-stack-specific detail that doesn't belong in the tool-agnostic `CLAUDE.md`.

**Reasoning:** `CLAUDE.md`'s rule is the general principle everywhere; `rules/gemini-agent-rules`'s rule is the same principle plus stack-specific elaboration for PHP projects. Removing either loses coverage for a different audience.

**Consequences:** Anyone editing the migration policy must update it in both places, or this will re-drift. Flagged in [TODO.md](TODO.md) as a candidate for consolidation if it drifts further.

## D4 — Never claim AI authorship of commits, docs, or code

**Context:** Explicit standing instruction in `CLAUDE.md`: "Never Claim work as yours for example, never say a commit, docs, code, etc. is authored by you (Claude, or some other AI agent)."

**Decision:** All work products from this repo's instructions (commits, docs, code) are written as if authored directly, with no AI-authorship watermark or attribution line in the content itself.

**Reasoning:** Owner preference, stated directly in the constitution file.

**Consequences:** Documentation and commit messages generated under these instructions must not include phrases like "generated by," "written by Claude," or similar attribution.
